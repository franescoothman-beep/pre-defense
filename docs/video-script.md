## 分镜

### 段 1｜0:00–0:30 痛点（口播 + 桌面）

- 画面：浏览器开一篇论文 PDF（或打印稿），手在纸上画问号
- 口播要点：答辩只有一次机会；"被追问到第二层"这件事，赛前练不到
- **不要**在这里介绍功能——痛点说清楚就走

### 段 2｜0:30–2:20 quick 档完整预演（主线素材 ①）

**演示路径**（MOCK 服务已在跑：`npm run demo` → localhost:3000）：

1. 上传页：选**内置样例**（`MOCK 演示模式` 角标必须在画面里）
2. 看板出现 3 位评委席位 → 第一问流式打出（**光标闪烁 + "正在发言…" 思考态要入镜**）
3. 答一题 → 评委追问（连续性提问是核心卖点，别跳）
4. 三问走完 → 点"结束并出报告"
5. 报告页：**点一条结论 → 原文高亮**（quote 类实色 / absence 类灰显，两类都要点一次）
6. 右栏临场表现的**评委打分散点**（一评委一点 + 竖线）
7. 复练入口点一下（drill 档：只比 performance，**画面里不能出现风险分差**）

**必须入镜的 4 个证据点**：MOCK 角标 / 思考态 / 原文高亮 / 散点。

### 段 3｜2:20–4:10 狗粮段（主线素材 ②：用它质询它自己）

**演示路径**（真实 key 模式，`MOCK_LLM=0`）：

1. 上传 `docs/eval/eval-03-self-dogfood.docx`（本作品说明书，476 块 / 71 条 claims）
2. 快进走完三问（可 2 倍速画面 + 口播"真实调用"）
3. 报告页停在**评委抓出的真实缺口**上（可复现性依赖 LLM 无固定手段 / 自查无重复执行记录等）
4. **当场改**：打开 `README.md` 或技术文档，把某条表述收窄（真实动作，慢慢打字）
5. **重跑**：再开一场，展示新报告里该缺口的变化

这段的意义：**报告的缺口是能落地的修改建议，不是套话**。

### 段 4｜4:10–6:30 AI 协同 ≥2min（硬性要求，必须独立时间码）

**素材来源：11-02 的 fresh-clone 实测**（见 `docs/ai-logs/20261102-fresh-clone-verify.md`）。
重演当天真实过程，报错是**真的**（删掉 `%LOCALAPPDATA%\next-swc` 缓存即可复现）：

1. 空目录 `git clone` → 按 README 原命令 `npm i --omit=optional`
2. `npm run demo` → **日志出现 `Downloading swc package...` 时停 5 秒**（给剪辑留定帧）
3. 口播：我的 README 写"零网络"，但它运行期在联网下载—— README 的话和实测对不上
4. **引导修复**（真实对话节奏，别照稿）：
   - "先只查这一件事：optional 里到底装了什么？" → 数 lockfile（72 个 optional 包）

5. 画面落点：`git log` 里 `4b584de docs: fix the install command after real fresh-clone verification`
   （**时间戳自证不是摆拍**）

**这段不许配 AI 生成的台词。** 修复路径当天真实发生过，照 `docs/ai-logs/` 复述即可。

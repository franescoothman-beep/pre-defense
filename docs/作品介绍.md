# 一、项目详情与使用方式

## 1.1 它是什么

**预演**是一个**答辩预演系统**：上传论文 / 项目文档 / 简历，三位方法论不同的 AI 评委轮番提问并追问，结束后给出一份**答辩风险报告**——报告里每一条结论都能一键追回原文那一句。

一句话概括它解决的问题：**正式答辩只有一次机会，但你可以先被 AI 问倒十次。**

它不是"AI 帮你问答"，区别在于三件事：会追问到你答不上来为止、每条结论都带可机检的原文锚点、改完材料能看见风险分真的下降。

## 1.2 一次完整的预演是什么样

| 步骤 | 用户做什么 | 系统做什么 |
|---|---|---|
| 1. 上传材料 | 拖入 PDF 或 DOCX（论文、项目文档、简历均可） | 逐页/逐段解析成**可定位的段落块**，每块带 `blockIdx + page + section`；PDF 走 `pdfjs-dist` 逐页抽，DOCX 走 `mammoth` |
| 2. 提取质疑点 | 无需操作 | 五阶段 Prompt 链的第一阶段：抽出材料里**可被质疑的主张**（claims），每条附原文引用与锚点 |
| 3. 被质询 | 逐条回答，可以只答一句 | 三位评委（方法论 / 工程 / 价值）按状态机顺序提问；答得含糊就**咬住追问**，答到位才换人 |
| 4. 看风险报告 | 点「结束并出报告」（随时可点，报告永不缺席） | 两栏报告：**材料风险**（越高越糟）与**临场表现**（越高越好），各分逻辑链 / 证据 / 技术深度 / 表达四维；顶部是「质询风险看板」，底部是「最可能被追问的点」按危险度排序 |
| 5. 追回原文 | 点任意一条质疑点或引用 | 跳回材料原文，**命中句直接高亮**；命中失败会明确标注，不假装成功 |

## 1.3 五种会话档位（默认是 quick）

| 档位 | 评委数 × 主问 | 追问 | 轮次上限 | 什么时候用 |
|---|---|---|---|---|
| `quick`（默认） | 3 × 1 | 每位至多 1 次 | 6 | 演示、录屏、日常快速体检：3–6 轮就出报告 |
| `full` | 3 × 3 | 每位至多 2 次 | 15 | 正式赛前完整体检 |
| `drill` | 3 × 2 | 每位至多 1 次 | 12 | **同一份材料**练回答，只比"临场表现"，绝不显示风险分差（同材料风险分永远是 −0） |
| `revise` | 3 × 1 | 无 | 6 | **上传改后的材料重新送审**，才比"材料风险"分差与质疑点增删 |
| `single` | 1 × 3 | 每位至多 2 次 | 8 | 降级：材料维度过窄、凑不齐三位评委时 |

`drill` 与 `revise` 是两条刻意分开的路径：**练嘴**只该看临场表现，**改材料**才该看风险分。把两者混在一个入口里，用户会永远看到"风险分 −0"，然后以为工具坏了。

## 1.4 两种运行方式（这是评委最该先看的一条）

| 方式 | 怎么进 | 需要 key 吗 | 说明 |
|---|---|---|---|
| **演示模式**（MOCK 回放） | `MOCK_LLM=1`，或页面上点「演示 · 零 key 回放」 | **不需要** | 按序号回放内置剧本，只允许内置样例；全程常驻「MOCK 演示模式」角标，绝不冒充真实模型输出 |
| **真实模型模式** | 右上角「真实 · 实时模型」 | 需要 `DEEPSEEK_API_KEY` | OpenAI 兼容接口，实时调用 |

评委**零 key** 就能走完上传 → 质询 → 追问 → 报告 → 追回原文的完整闭环。切换入口只有一个（`/api/mode` 总闸），不存在"一半 mock 一半真实"的混合态。

## 1.5 十分钟复现

```bash
git clone https://github.com/franescoothman-beep/pre-defense.git
cd pre-defense && npm install
cp .env.example .env.local      # 演示模式不需要填任何 key
npm run demo                    # 起服务并跑通一次内置样例
```

实测（本机 Windows 11 / Node 24）：clone 5.4 s、`npm install` 108.6 s、`npm run demo` 4.4 s，零 key 闭环产出材料风险 75 分。完整环境说明、依赖清单、`.env` 模板与故障排查见仓库根目录 `README.md`；技术论证见 `docs/technical-doc.pdf`（17 页）。

# 二、项目亮点

1. **每条结论都能追回原文那一句。** 评委会说的每句话都要附一个锚点：指向材料的第几块、哪一页、哪一章，外加**原样引用**。系统对引用做**逐字机检**——编出来的、改了字的、拼接的，全部判不通过，该条结论不会进入报告的算分口径。引用类（`quote`）与"材料里根本没有"类（`absence`）在视觉与统计上都是两套：`absence` 走的是范围合法性校验，**不进命中率分母**，不做"查不到就算你对"的偷懒。

2. **三位不同方法论的评委会咬住不放，但收敛由代码决定。** 追问不是"再问一句"，而是带着目标质疑点往下压；什么时候换评委、什么时候结束、什么时候必须出报告，写在 `lib/state.ts` 的纯函数里，**不交给模型自觉**。quick 档 3 位各 1 主问 + 至多 1 追问，3–6 轮必出报告——报告永不缺席。

3. **一份报告，两个分数，两套颜色，绝不混用。** 材料风险的 `risk_score` 由**服务端从质疑点聚合**（越大越糟），模型只负责写评语；临场表现的 `performance.score` 由模型出分（越大越好）。两者不同名、不同色阶、不同图例，避免"模型给自己打分"和"材料分被模型随口改"这两类污染。

4. **改材料能看见风险真的下降。** `revise` 闭环：上传改后的材料 → 重新审 → 给出风险分差与质疑点增删对比。这是唯一能证明"风险是可下降的"路径，也是本作品区别于"AI 聊天套壳"的地方。

5. **零 key 一键复现，且有证据。** `MOCK_LLM=1` 的 fixture 回放让评委不配任何 key 就能走完闭环，界面全程挂着 MOCK 角标；同时 `npm run test:fixtures` 用**当前 schema** 校验全部 51 条回放序列，防止 mock 静默返回旧结构。

6. **数字都能被复算，不是形容词。** 467 条单测、51 项 fixture 校验、真实材料引用逐字命中 86.8%（79/91）、双采样一致性 3/3、内置样例引用命中 11/11——每条都写在 `README.md` 的「数字与可复现证据速查」里，附复算命令。

# 三、AI 技术落地情况

## 3.1 运行时：五阶段 Prompt 链

AI 不是"一个聊天框"，而是一条**有契约的流水线**。每一阶段的输入输出都被 zod 锁死，模型无法跳过或改写结构。

| 阶段 | 输入 | 输出（受 schema 约束） | 关键约束 |
|---|---|---|---|
| `claims` | 材料段落块 | 质疑点数组：`text` + 锚点 `{blockIdx, page?, section?, quote, kind}` | 每条必须带锚点；`quote` 必须能在该块内逐字命中 |
| `personas` | 质疑点 + 材料元信息 | 三位评委画像与席位分配 | 材料维度不足时按 `planSeats` 减席，宁少不凑 |
| `question` | 当前评委 + 目标质疑点 + 已问历史 | 一条主问 + 目标 `claim_id` | 同一 claim 全场只被 targeting 一次 |
| `evaluate` | 用户回答 + 被问质疑点 | 追问（可空）+ `resolved` 布尔 + 维度得分 | `resolved=true` 即结束本轮，不许没完没了 |
| `report` | 全部问答 + 质疑点 | 四维评语 + 临场表现分 + 最可能被追问的点 | **材料分不由模型给**，由服务端聚合 |

## 3.2 三道机检：模型说什么不算，机检过了才算

1. **结构机检**——所有 LLM 输出必须过 `lib/schemas.ts` 的 zod 校验，多字段、少字段、类型错，一律进入重试/兜底，不写库。
2. **引用机检**——`lib/locator.ts`：`quote` 型锚点在该 block 内做逐字匹配（长度 8–60 字），命中才算有效；`absence` 型锚点在声明的 scope（≤60 字）内**确实找不到**才成立。
3. **状态机机检**——`lib/state.ts` 的 `decide()` 是纯函数，输入快照与模型输出，输出 `ask / followup / end`，任何一条规则命中都让流程前进，**永不返回"再等等"**（预算 30 次、轮次上限、20 分钟空闲、追问重复度 >0.8、claim 已问过等）。

## 3.3 流式与思考态

质询走 **SSE**：评委"正在读你的材料 / 正在想要不要追问"的思考态、逐字输出的提问、追问接续，都是同一条事件流推下来的。这是官方评分里"如流式、思考可视化"的直接落点——不是加载动画，而是把模型的中间状态显式化。

## 3.4 开发期：AI 是主要生产力，但每个结论都要被证明

| 环节 | 用的 AI | 产出 |
|---|---|---|
| 架构 / 重构 / 测试 | Claude Code | `lib/` 19 个模块（纯函数优先）、467 条单测 |
| UI 与实现 | Trae CN（GLM-5.3-flash / DeepSeek-4.1-flash） | 「朱批 · 多材质」视觉落地、组件与交互 |
| 运行时推理 | DeepSeek API | 五阶段链的实际推理 |

**可核查的协同证据**：

- `docs/ai-logs/` **38 篇**过程记录，每篇固定六段：目标 / Prompt 原文 / AI 输出摘要 / 我的修改 / **Bug 与修复过程** / 遗留问题 + commit（37 篇含 Bug 小节）。一次 AI 会话 = 一个 commit，仓库 74 个提交没有 `initial commit` 或 `update` 这类无法追溯的提交。
- `docs/prompt-eval/` **三组 v1 vs v2 同输入对比**（claims / evaluate / report），每组含两套 system prompt 与原始 JSON 输出，附 `diff.md`。
- 演示视频里有 **≥2 分钟**的 AI 协同实录：现场输入 Prompt 让 AI 生成核心模块、以及引导 AI 修一个顽固 Bug 的全过程。

**五条被 AI 写出来的"静默失败"**（能跑、但结论是错的——这才是 AI 编码真正的风险）：

| 事故 | AI 具体错在哪 | 修复 |
|---|---|---|
| mock 回放串问 | 游标单 key + 热重载归零，双根因叠加 | 键改 `sessionKey:phase`，并挂到 `globalThis` |
| fresh clone 走不通 | 空库无样例 + claim_id 对不上 | 保真导出种子 + 幂等播种 |
| 评测命中率恒 0 | `verifyQuote` 参数签名写错，把"全命中"报成"全未命中" | 改三参调用 |
| 越界判据永远 false | `z.object` 静默 strip 未知字段 | 改读模型原始输出 |
| 400px 横向溢出 | 误判 `max-width` 为根因（它撑不宽父容器） | iframe 探针定位到单行 flex |

这五条直接决定了本项目的测试策略：**重点不是用 lint 证明语法，而是用机检证明结论**——所以才有 467 条单测与 51 项 fixture 契约校验。

## 3.5 诚实的边界（写在文档里，也写在 README 里）

- 材料风险分**不是模型打的**，是服务端按质疑点的严重度聚合的；模型只写评语。这样做是因为"让模型给材料打分"无法复现，也无法解释某一分是哪条质疑点贡献的。
- `absence`（材料里缺什么）与 `quote`（材料里写了什么）分开统计，绝不混进同一个命中率。
- 不支持：扫描版 PDF（无文字层）、PPTX、无分页信息的 DOCX。README 明写，界面会给提示，不装作能处理。

# 四、关键技术

| 维度 | 选型 | 为什么是它 |
|---|---|---|
| 框架 | Next.js 15.5.28（App Router）+ React 19 + TypeScript | 前后端一体、Route Handler 天然适配 SSE；版本锁死，不追 16 |
| 样式 | Tailwind v4 + CSS token（组件内不写十六进制色） | 「朱批 · 多材质」需要一套可换的主题变量，颜色只走 `app/globals.css` |
| 存储 | **`node:sqlite`**（Node 24 内置） | 零原生编译、零额外服务；`npm install` 在评委机器上不会因 node-gyp 失败 |
| 契约 | zod 4.6.7 | 每个 LLM 输出先过 schema 再入库，坏结构不进库 |
| PDF 解析 | `pdfjs-dist@5.4.149`（逐页，`--omit=optional` + canvas polyfill） | 需要页码；换来的代价是装依赖时多一步 polyfill，已脚本化 |
| DOCX 解析 | `mammoth` | 只取段落与标题层级，够用且轻 |
| 溯源 | **锚点模型**：`blockIdx + page? + section? + quote + kind` | 纯页码在重排版后全错；锚点 + 逐字机检才能既定位又防编造 |
| 调度 | **状态机控制的顺序提问**（`lib/state.ts` 纯函数） | 多角色不是自由协作的 Agent 群：自由协作无法保证"3–6 轮出报告" |
| 流式 | SSE（`app/api/sessions/[id]/stream`） | 思考态与逐字输出同源，前端无需轮询 |
| 复现 | `MOCK_LLM=1` fixture 回放（序号驱动、仅内置样例） | 评委零 key 走完闭环；同时是回归测试的地基 |
| 安全 | S1–S6 基线：上传类型/大小校验、路径穿越防护、prompt 注入隔离、不用 `dangerouslySetInnerHTML` 渲染模型输出等 | 上传的是别人的论文与简历，模型输出不可信 |

**规模**：`lib/` 19 个模块、`app/api/` 13 个 Route Handler、`tests/` 35 个测试文件 / 467 条单测。

# 七、是否基于其他项目优化

**不是。本项目从零构建，未复用任何既有项目的代码。**

- 仓库首个提交为 2026-11-01 的项目骨架，此后 74 个提交按功能模块逐个落地（每次 AI 会话一个 commit），**不存在 "initial commit 即全部功能"** 的情况，可按提交历史逐条核对演进过程。
- 开发者此前另有 CodeSpire、spire-nexus 两个项目，本次仅把它们当作**架构经验参考**（例如"解析层与推理层分离"的取舍），**未复制任何文件、目录或依赖配置**；本仓库的直接依赖只有 6 个（next / react / react-dom / zod / pdfjs-dist / mammoth，外加 tailwind 工具链），可对照 `package.json` 核验。
- 与官方推荐选题的关系：本作品是官方推荐方向 1「多角色对抗质询系统」的**独立落地实现**，选题方向一致，代码与设计自主完成。

# 2026-10-31 阶段 3 第 0 条：真实 key 验证 personas + POST /api/sessions

## 目标

用**真实 DeepSeek key** 跑 `POST /api/sessions`，检查三件事（`指令包.md §4` 第 0 条）：

1. 3 位评委是否各自落到不同类型（method / engineering / value）
2. 每位 `opening` 的 `claim_id` 能否对上库里的真实 claim
3. 三位 `focus` 的 `dimension` 是否两两不同

> 前置事实（`progress.md` 接力棒）：样例 docId `86322517-36ae-46cc-8dfa-300150d283dd`，
> 10 块 / `mode=flow` / `density=thin`，12 条 claims，
> 类型分布 `method 10 / engineering **0** / value 2`，
> 维度分布 `logic 4 / evidence 5 / depth 3 / expression **0**`。

## Bug 与修复过程（真实记录）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **`POST /api/sessions` 100% 返回 502**（`E_SCHEMA`） | `PersonasOut` 把 `color` 设成**必填**（`regex(/^#[0-9a-f]{6}/)`），而 `PERSONAS_SYSTEM` 明文「**不要输出 color 字段**（服务端按维度分配传统色）」。模型照 prompt 做 → zod 校验必然失败 | `lib/schemas.ts` 删掉 `color` 字段，并在原位写下"为什么不能要它"的注释；`app/api/sessions/route.ts` 的 `as` 类型断言同步去掉 `color` |
| 2 | `anchor.blockIdx` 恒为 `null` | 路由里硬编码 `blockIdx: null`（注释写"由 turns 表或 claims 查得"），但 `loadClaims` 的 SQL **根本没 select `block_idx`** | `ClaimForPersona` 加 `blockIdx`；`loadClaims` 补 `block_idx` 列；路由改用 `firstClaim.blockIdx`。实测从 `null` → `3` |
| 3 | **三位评委串味**：engineering 评委问的是「从相关到管理结论的因果推断链条」（method/logic 面） | 材料 `engineering` 类 claim **0 条**，而旧 `assignDims`/`buildPersonasUser` 按「method/engineering/value 三位类型齐全」硬分席位。候选为空时 prompt 还直接写「请仍然生成这位评委，opening 只能引用**其它类型**的候选」——**等于把串味写成了合法行为** | 重写为 `planSeats()`：按**真实存在的（维度, 类型）组合**排席位，维度强制两两不同，候选只装本维度的 claim；路由新增**锚点归属校验**（第 i 位只能用第 i 席的 claim_id），跨席借用直接丢弃并 `console.warn` |
| 4 | 席位没填满时静默少评委 | 旧代码 `validated.slice(0, matrix.judges)` 静默截断 | 改为按 `seats.length` 一一对齐，`validated.length < seats.length` 时打 warn；响应新增 `coverage.seated / coverage.absent` **如实报告哪几维材料本身就没有**（不假装有） |

> **#1 是本阶段最有价值的一条**：mock 全绿也抓不到它 —— `fixtures/llm/personas.json`
> 是我自己手写的，带不带 `color` 都不会报错。只有真实模型**遵守 prompt** 时才会撞上。
> 这正是 `progress.md` 的 v2.1.3 第⑥条「mock 全绿 ≠ 真实可用」的第二次现形。
> 更严重的是之前的 96 个单测里**没有一个测过 `PersonasOut`** —— 才让这个矛盾活到提交之后。

> **#3 印证了文档预判**：`开发流程详细文档.md §阶段 3` 已写明
> 「第 0 条验证大概率暴露『评委类型重复』或『借用其它类型 claim』」。
> 修法选了**方向 A（按实际存在的 dimension 分配）**而非方向 B（改 claims 抽取要求覆盖三类）：
> 材料的质疑点类型由材料本身决定，硬凑只会让三位评委问同一件事；
> 缺哪一维就如实报 `coverage.absent`，比伪造一位评委诚实。

## 修复后复验（真实 key）

```
三位席位：evidence/method → logic/method → depth/value
focus：样本代表性与数据采集范围能否支撑推广结论
      从相关到因果的逻辑跳跃与混杂控制
      模型相对既有研究的增量价值与可落地性
coverage.absent: ["expression"]
首问 claimId=d6a27be9… anchor.blockIdx=3 quote 逐字命中 verified=1
```

- 三位维度两两不同，且**不再有假 engineering 评委**
- 首问锚点四件套齐全（`blockIdx` / `quote` / `locatorKind` / `verified`）

## 我的实测与判断（这轮真正的产出）
1. **`create-next-app` 在本机写 `%APPDATA%\create-next-app-nodejs\Config` 被拒（EPERM）**
   → 放弃脚手架生成器，改为手写最小骨架（package.json / tsconfig / next.config / postcss / app/*）
2. **`npm i` 在本机默认 cache 目录 EPERM**
   → 统一用工作区内 `--cache .npm-cache`；README 里写清复现方式（评委机器没这个限制，但我要能复现）
3. **pdfjs-dist 版本与原生依赖**
   - 6.4.299 可选依赖 `@napi-rs/canvas@^1` → 落 28MB `skia.win32-x64-msvc.node`（实测 spike 目录 99.9MB）
   - 5.4.149 + `--omit=optional` → 34.5MB，**仍能逐页取文本**
   - 结论：锁 5.4.149，并自写 `scripts/polyfill-canvas.mjs` 补 `DOMMatrix/Path2D/document`
4. **officeparser@8 依赖 tesseract.js（WASM OCR）+ 自带第二份 pdfjs**
   → DOCX 改 `mammoth`（纯 JS），**PPTX 不做**
5. **中文 PDF 逐字空格化**：不处理时输出 `教 育 背 景  闽 南 科技学 院`；
   按 y 容差 2.5 聚行 + x 排序 + 去汉字间假空格后，输出 `教育背景 闽南科技学院…`，汉字间空格残留 0

## Bug 与修复过程（真实记录）
| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `hits()` 对「两人 独立标注」判不命中 | 归一化只压空白不去空白 | `hits` 改为**去全部空白后 includes**（中文语料可接受，写进局限） |
| 2 | `verifyQuote` 原地命中失败（actual 0 expected 1） | 测试里 quote 只给 6 字，低于 8 字门槛 | 测试改用 12 字；**产品逻辑不动**（门槛是对的） |
| 3 | `isSection` 对「第1章 研究背景」判 false | 正则要求整行只有"第X章" | 改为**行首命中 + 行长 ≤48**，`isSection` 单一出口 |
| 4 | `SyntaxError: Identifier 'isSection' already declared` | 替换时旧函数体残留 | 删重复定义 |
| 5 | Node 测试报 `Cannot find module '.../lib/normalize'` | Node ESM 要扩展名，Next bundler 不要 | 加 `tests/hooks.mjs`（`registerHooks` 补 `.ts`），**产品代码保持 Next 友好** |
| 6 | `node --test tests/` 报 EPERM spawn | 沙箱禁管道 spawn | 改为按文件跑 `--test "tests/*.test.ts"` |
| 7 | Next build 报 `spawn EPERM` | SWC 编译器 worker 用管道 stdio | 显式装 `@next/swc-win32-x64-msvc` 后仍需放宽沙箱一次 |

# 2026-10-31 · 阶段 2：质疑点抽取 + 卡片页

## 目标
1. `lib/llm.ts`：OpenAI 兼容 + zod + 重试 1 次 + 预算计数 + `llm_logs`（只存 hash）+ MOCK 分支
2. `lib/prompts/claims.v1.ts`：每批 5 块，输出 `type/text/block_idx/kind/quote/scope/risk/dimension`
3. `POST /api/docs/:id/claims`：抽取 → 回填 page/section → `attachLocator` 机检 → 写 claims → 返回两组比率
4. 卡片页：按类型三栏 + 风险星级 + **点开展开原文并高亮 quote**
5. `fixtures/` 内置样例 + mock 回放数据（零 key 可复现）

## Prompt 原文（要点）
- "只做到质疑点卡片为止，不进入提问环节"
- "每条必须带 block_idx、kind（quote | absence）、quote（8–60 字，必须原文逐字）、scope（absence 时必填）"
- "模型不输出 page/section，由服务端按 block_idx 回填"
- "kind 的存在意义：像'你缺对照组'这类质疑在原文里根本没有可引用的句子，不给 absence 出口，模型只能编一句假引用"

## 我的判断与取舍

1. **mock 必须过同一套 zod**（`lib/llm.ts` 的 `callMock` 里显式校验）。
   若 mock 绕过 zod，就会在评委机器上静默通过一个真实模式会失败的响应——那等于"复现"是假的。
   这条是本阶段最重要的一行代码。

2. **预算检查放在分支之前**，因此 mock 也受限。让"mock 下的行为"与"真实下的行为"在预算维度一致。

3. **fixture 的 quote 不手写，全部由脚本从 blocks 里切片生成**（`scripts/make-claims-fixture.py`）。
   手写 quote 少一个字、改一个标点，机检就判 `verified=0`；而演示时没人会逐字核对，
   命中率会静默掉一截。脚本化生成从根上消除这个失败模式。

4. **fixture 的块号必须落在真实批次里**。路由有 `if (!batch.includes(c.block_idx)) continue;`
   （防模型编造块号）。我第一次凭想象把 6 条 claim 平均分成两批，结果真实批次是 `[[1,3,4,6,7],[9]]`，
   第二批只有一块——凭想象写的 fixture 会被逐条丢弃。

5. **卡片页展开时显示整块原文，不是只显示 quote**。
   用户要判断的是"这句话**是否支持**这个结论"，而不只是"这句话**是否存在**"。
   只给 quote 就无法发现语义被曲解——而"命中≠支持"正是第 6 章要诚实写出的局限。
   为此给 API 加了 `source` 字段（POST 与 GET 都带）。

## Bug 与修复过程（真实记录）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `buildClaimsUser` 渲染出空片段 | 用 `blocks[idx]` **按数组位置**取块，但第二个参数是**块号**；`batchesOf` 会跳过短块导致两者错位 | 改为 `Map<idx, Block>` 按编号查找；找不到就明确告诉模型"本批没有可用片段，返回空数组"，不让它硬编 |
| 2 | 抽出的 claim 只有 4 条，而且 section 全是 null | 上传的 DOCX 只解析出 **6 块**（标题与正文被合并） | 见 #3 |
| 3 | **DOCX 标题未被识别，与正文合并成一块** | `SECTION_HEAD` 正则要求"数字后直接跟汉字"，而「1. 研究背景与意义」是**数字 + 点 + 空格 + 汉字**，漏判 | 正则改为 `\d+(?:\.\d+)*\s*[.、::]?\s*[汉字]`；补 5 个 isSection 回归单测。修复后该样例从 6 块变 10 块，section 正确回填 |
| 4 | **重抽一次质疑点全没了（第二次返回 0 条）** | mock 游标不复位，第二次从 seq 末尾继续 → `E_MOCK_MISS` | `lib/llm.ts` 加 `resetMockCursor()`，claims 路由在 mock 下重抽前复位 |
| 5 | `loadAll('claims')` 单测失败 | 测试断言"当前尚无 fixture"，但阶段 2 已经把 fixture 提交了——这是**测试预期随数据变化而陈旧**，不是产品 bug | 改为断言真实语义：fixture 存在且结构完整 |
| 6 | 单测里 `new Uint8Array([...]), 'docx'` 括号放错位置 | 手写断言时把 `'docx'` 放进了 `sniffKind(` 而不是 `assert.equal(` | 逐行修正；后续改用更短的断言形式 |
| 7 | 卡片页 CSS 里误入一行 `GE: none;` | 手写 CSS 时的残留字符 | 改为完整的 `.meta` 规则（flex + gap + wrap） |
| 8 | `Start-Process -Environment` 报参数不存在 | Windows PowerShell 5.1 的 Start-Process 无此参数 | 先用 `$env:MOCK_LLM="1"`，子进程继承环境变量 |
| 9 | **大材料只审了前 60 块，却不说** | 原写死 `slice(0, 12)`：101 页论文 480 批只取前 12 批 = 只看了 2.5% 的材料，报告看起来完整 | 改**均匀采样**（首/中/尾都覆盖），并在响应里返回 `coverage`，卡片页显式提示"跳过了 N 批，未抽到的部分不等于没问题" |

> **#3 是本阶段最有价值的一条**：它不报错、不崩溃，只是"少解析出几块"。
> 后果是整份材料的 `section` 全部错位，而溯源产品一旦 section 错了，
> 用户点开"§2. 数据与方法"却看到标题行——信任瞬间崩塌。这类静默错误比崩溃危险得多。
>
> **#4 同样危险**：用户点一次"重新抽取"就把结果清空了，且没有任何报错。
> 之所以能发现，是因为我把"重抽幂等"写进了 smoke 脚本——**断言"第二次结果不比第一次少"**。

## 我的判断与取舍

1. **状态由外部传入，组件不自己算**。"谁在说话"是状态机（`lib/state.ts`）的结论，
   展示层再推一遍必然分叉——分叉的第一现场就是"横条高亮的人和正文里的发言人不是同一位"。

2. **`current` 判定必须优先于 `past`**。若先判 `past`，"正在说话且已问过"的评委会同时被
   高亮和降透明度，等于告诉用户"这个人已经问完了"+"他现在正在说话"两个矛盾信号。
   这条写成了测试（`bench.test.ts`）。

3. **`dimension` 存进库，不做"按 color 反查"**。横条标签的四维传统色要按维度选。
   若前端把 `#7c6a8a` 反查回 `evidence`，等于在展示层复制一份配色映射，
   以后调色一改就错位。所以给 `personas` 加 `dimension` 列（排席位时本来就定了）。

4. **样式硬规格做成自动测试**。四条规格（无十六进制 / 字号 5 级 / 无圆角 / 180ms）
   写进 `tests/bench.test.ts`，以后谁"自己发挥"就当场红。

## Bug 与修复过程（真实记录）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `GET /api/sessions/:id` 返回 `personas: []`，页面显示"没有评委" | 脚本直接插 `sessions` 表、personas 没挂 `session_id`，而读取只按 `session_id` 取 | `loadPersonas` 改三级取法：① 按 session_id → ② 旧数据（`session_id is null`）→ ③ **按 doc 兜底 + `console.warn`**。兜底必须带 limit，否则多轮人设一起返回会让取模错位 |
| 2 | 页面 HTML 里只有"正在读取"，看不到 seat 标记 | 组件是 client-side，首次渲染数据未到——**这是预期行为**，不是 bug | 改为从构建产物验证：确认 `bench-seats` / `.seat.is-past` / `@keyframes seat-breathe` / 720px 断点都已打进 `.next/static/css` |
| 3 | `dimension` 拿不到 | API 只返回 `color`，`personas` 表也没有 dimension 列 | 加列 + `ensureColumn` 迁移 + 写入侧带上 `p.seat.dim` + 读取侧直接用 |
| 4 | `roundLabel` 类型报错（返回 `string \| undefined`） | 组件类型要求 `=> string`，回调里写了条件返回 | 去掉条件，恒返回座位序号 |

> **#1 值得单独说**：它不是"我造数据造错了"那么简单。真实场景里，
> 迁移中断、脚本直插、将来 `revise` 复用 doc 都可能出现"会话在、人设没挂上"。
> 若读取侧死抠 `session_id`，页面会静默显示"没有评委"——用户看到的是产品坏了，
> 而不是数据写错了。所以兜底 + 告警是必要的，告警让这条走了兜底的路径可被排查。

## 需要用户拍板的一件事

**呼吸点算不算第 5 处动效？**

- 用户明确要求"当前说话者朱红下划线 + **呼吸点**"，所以做了 `animation: seat-breathe 1.05s steps(2,end)`
- 但 `§3.2` 的动效硬规格写"只允许 4 处"，且 4 处清单里没有"呼吸点"这一项
- 本次实际动效来源 = 2 个：`transition opacity 180ms`（评委切换 #3）+ `seat-breathe`
- 若严格按"这次只做评委切换 180ms"，呼吸点应做成**静态小色块**（无 animation）

**待定，倾向保留**：呼吸点是与下划线共同构成"当前者"的标识，且与清单里 #1「token 光标闪烁 1.05s steps」同类同参，可按"1.05s steps 系"归并。但这是产品口径问题，须用户确认。

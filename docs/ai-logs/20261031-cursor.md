## 1. 前置修改：呼吸点改静态

**问题**：上一拍给评审席"呼吸点"加了 `animation: seat-breathe 1.05s steps(2,end)`。
而用户硬规格是「动效只允许 4 处，**这次只做评委切换 180ms**」——呼吸点等于悄悄加了第二处动效。

**修法**：去掉 animation，保留"点"这个标识（实心朱红＝正在说话，压暗＝没轮到）。
新增测试钉死：`animation` / `@keyframes` 不得出现，`transition` 只许一处且必须 `opacity 180ms`。

> 这条是"守规格"，不是"改审美"。点的**语义**保留，**动**的部分还给了硬规格。

## 2. 接流（`EventSource`）

**为什么用 EventSource 而不是 `fetch` + `ReadableStream`**：
四事件是标准 SSE，EventSource 自带行解析与断线处理，少写一套解析器；
服务端已把 `{"question": ...}` 解包成纯人话，前端只做字符串拼接。
代价：不能带自定义请求头——本接口不需要鉴权，可接受。

**事件处理**：

| 事件 | 前端动作 |
|---|---|
| `meta` | 记录 persona / claimId / blockIdx / source；**phase 立刻进 `live`**（光标从这一刻开始闪，不等首字） |
| `token` | `setStreamText(prev => prev + t.t)` —— 逐字追加，这就是"流式肉眼可见" |
| `done` | 记录 turnId / latency；**phase 进 `done` → 光标消失**；`es.close()` |
| `error` | 服务端给的 `fallback` **原样展示**（不再翻译）；`es.close()` |

## 3. 光标规格落地

```css
.cursor {
  display: inline-block;
  width: 2px; height: 1em;
  margin-left: 2px;
  vertical-align: text-bottom;
  background: var(--red);          /* 朱红 token，不写十六进制 */
  animation: cursor-blink 1.05s steps(2, end) infinite;
}
@keyframes cursor-blink { 0%,100%{opacity:1} 50%{opacity:0} }
.cursor.is-done { display: none; }  /* done 即消失，不是只停动画 */
```

- **`steps(2,end)` 而非渐变**：§3.2 写的是"闪烁"，观感应是打字机光标，不是柔光呼吸
- **`is-done` 用 `display:none`**：只停 animation 会留下一个常亮方块，看起来像还在打字

## Bug 与修复过程（真实记录）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **`es.close()` 之后浏览器补发一个连接层 `error`，正常结束会被画成"中断"** | 用 `setPhase(p => p === 'done' ? p : 'error')` 判断，依赖"上一次 setState 已被 React 应用"的时序；StrictMode / 并发渲染 / 批处理都可能让 `p` 还是旧值 | 改用 `finishedRef`（ref 是即时生效、不经过渲染队列的）显式记录"我自己关的"，连接层 error 一律忽略；每次开新流重置 |
| 2 | 测试断言"不做输入框/localStorage"**误报** | 测试读全文，而页面顶部说明性注释里写着"不做输入框、不做 localStorage" | 测试改为**先剥掉注释**再匹配（`codeOf()` 辅助函数）。同类问题在 `onmessage` 那条也出现过一次 |
| 3 | 验证时页面跑的是**旧构建** | 端口 3111 有 21:23 启动的残留进程，新 `next start` 因 EADDRINUSE 静默退出 | 确认 PID 启动时间早于本次构建 → 杀掉 → 重启（新 PID 38188），并**核对页面引用的 CSS 哈希**（`c6fe01ec…`）与产物一致 |
| 4 | 用 `<textarea>` 查输入框会误伤 JSX 注释外的说明文字 | 同 #2 | 统一走 `codeOf()` |

> **#1 是本轮最值钱的一条**：它不报错、不崩，只是在**正常结束时**偶发地把界面画成"中断"。
> 这类 bug 最难查——现象是"有时候好好的，有时候显示中断"，而代码看起来完全合理。
> 根因是"用渲染状态判断即时事实"，修法是换成 ref。**凡是"我刚做了什么"的判断，都不该走 setState。**

## 二、做了什么

### 1. `lib/report.ts`（459 → 约 560 行）

原来只有 `aggregateMaterialRisk` / `normalizePerformance` / `computeDelta`（**写好但全库从未被调用**）。
补上三组能力：

| 新增 | 作用 | 关键约束 |
|---|---|---|
| `overallOfCells` | 报告封面那个大数字 | 从**已落库格子**加权，不重读 claims——"重新抽取"会换掉 claims，历史报告的数字不能跟着变 |
| `overallScoreOf` | 临场表现的总分 | 只平均非 null 的维，全 null 返回 null（不补 0，0 分和没问过是两件事） |
| `boardOf` | 看板矩阵 | 行是**质疑类型**不是评委，见下 |
| `claimDiffOf` | 质疑点增删 | 归一化对齐（见下） |
| `deltaFor` | 二练对比的组装 | 无上一场 / 解析全空 → null，页面上是"这一次没法比"而不是"没有改善" |

**看板为什么按"质疑类型"分行，而不是按"评委"分行**：

`planSeats` 在材料维度不足时会用「同维度、另一类型」补位，所以完全可能两位评委同为 `method`。
按评委分行 → 两行数字一模一样，读者会以为看板坏了；按类型分行（方法论 / 工程实现 / 价值与创新）
永远三行、永不重复，行头再标出占该席的评委名，视觉与信息量都不丢。
格子里的 risk 直接复用 `aggregateMaterialRisk(sub)`，与左栏**同一套权重**——评委能拿页面上的格子当场验算。

**`claimDiffOf` 的对齐键**：`s.replace(/[\s\p{P}\p{S}]/gu, '')`。
不这么做，「样本量够吗？」和「样本量够吗。」会被算成"删一条、加一条"，
而真实情况是模型在同一个质疑点上换了措辞。先按归一化 text 对齐，再按归一化 quote（≥8 字）兜底。

### 2. `app/api/sessions/[id]/end/route.ts`

在 `coverageOf` 之前插入二练对比块：`prevReport` 取自 `select * from reports where session_id = ?`（`session.drillFrom`），
`delta = deltaFor(...)`，落库 `delta === null ? null : JSON.stringify(delta)`。

**必须在出报告时算完落库，不能在读接口现算**：`revise` 的上一场 claims 可能已经被"重新抽取"换掉，
现算会让同一份历史报告每次打开数字不同，直接违反"可复现"。

### 3. `app/report/[id]/page.tsx`（506 → 约 700 行，方向 E 定稿）

结构：封面带（朱印数字 = `overallRisk`，kicker 按档位换文案）→ 覆盖缺口 → 审议轨迹条 →
**质询风险看板** → `DeltaBlock` → 两栏 → 点开的引用 → 高风险清单 → advice → 轨迹明细 → 复练入口 → 页脚。

- 看板格子：`count === 0` → 灰色「—」**不可点**；有数据 → `<a href="/doc/{docId}?dim=&type=">`，
  格内是分数 + 条 + 「N 条 · 问过 M · 缺 K」
- `DeltaBlock` 按 `kind` 分叉：`revise` 渲染风险行 + 质疑点增删；`drill` 渲染表现行 +
  一句自证「这一场材料一个字没改，所以风险分不会变」
- 正负色也分叉：`revise` 是 `diff < 0` 为好（风险下降），`drill` 是 `diff > 0` 为好（表现提高）。
  两条路径共用一个颜色映射就会出现「绿色 = 变差了」
- **删掉了阶段 4 的 `report-next`「本页尚未完成的部分」整节**——留着就是让页面说谎

### 4. 两条复练路径的入口（这一阶段才发现入口原本是断的）

查代码时发现：**全仓库没有任何 UI 入口能创建会话**。

README 第 20 行却写着「选内置样例 → 开始质询 → 出报告 → 复练」——

  `startSession()` → `POST /api/sessions` → `router.push('/session/' + id)`；

用 `window.location.search` 而不是 `useSearchParams`——后者要求 Suspense 边界，否则 build 直接报错。

## 四、真实 Bug 与修复过程（3 条 + 2 条环境坑）

### Bug 1：`MODE_MATRIX.drill` 的轮次上限比主问配额还小

旧值 `{judges:3, mainsEach:2, followupsEach:1, maxTurns:5}`：主问要问 6 个，但轮次只给 5 轮。
规则 7（撞上限即收口）会在「3/6 主问」时把会话掐断——用户看到的不是"练完了"，而是"系统提前放弃了"。

第一次真实探针的下场就是这样：drill 跑到第 3 个主问就 `decision=end`，
而脚本还"通过"了——因为断言只查了 delta 形状，没查**它是不是练够了**。
**修法**：`lib/state.ts:72` 改 `maxTurns: 8`；并把 `tests/state-stage4.test.ts` 里那条
`MODE_MATRIX.drill.maxTurns === 5` 的断言换成不变量测试：**所有 mode 都必须 `maxTurns >= judges * mainsEach`**。
锁死具体数字只会让下一个人再踩一次，锁死不变量才能拦住同类错误。

### Bug 2：S3 安全扫描把「写禁令的地方」判成「违反禁令的地方」

`tests/stage5-report.test.ts` 断言报告页 `doesNotMatch(/dangerouslySetInnerHTML/)` 失败——
因为我在页面注释里正写着"这里绝不使用 dangerouslySetInnerHTML"。
**修法**：先剥注释（`/\/\*[\s\S]*?\*\//g` 与 `^\s*//.*$`）再断言。
与 `tests/security-baseline.test.ts` 的 `stripCommentsAndLiterals` 同理（未导出，本地实现一份并写明理由）——
教训是：全文搜禁词，命中的永远包括禁令本身。

### Bug 3：阶段 4 的测试断言"本页尚未完成的部分"存在

`tests/stage4-ui.test.ts:144` 断言报告页含「本页尚未完成的部分」。阶段 5 把那一节删了，测试就红了。

## 七、录屏后的遗漏补修（第二轮，2026-11-01 15:00）

录屏结束、服务可安全重启后，把 §六 之前的遗留清了三件：

### 补修 1：drill 的轮次预算只够"问得完"，不够"练得完"

阶段 5 第一轮把 drill 的 `maxTurns` 从 5 提到 8，当时守的不变量是 `maxTurns >= 主问配额`。
这条不变量**只保证问得完，不保证练得完**：追问也是 turn，会挤掉还没问的主问。

正确的最坏情况公式：`worst = 配额 + (配额 − 1) × followupsEach`
（「主问配额用尽即收口」在最后一条主问**答完的那一拍**触发，所以最后一条永远分不到追问）。
drill 按公式 = 6 + 5×1 = 11，`maxTurns=8` 仍不够 —— 探针实录就是在 4/6 主问被规则 7 掐断。

**修法**：`drill.maxTurns` 提到 12；`single` 按公式 3+4=7 也提到 8。
测试从"锁死数字"改成**两条不变量**：① `maxTurns >= 配额`（所有 mode）；
② `maxTurns >= worst`（full 除外——官方口径"full 才 ≤15 轮"是写死的硬顶，追问预算被挤掉是文档行为）。

复跑探针：drill 跑满 **6/6 主问**才收口（"主问已问完（6/6）→ 立刻出报告"），不再提前放弃。

### 补修 2：看板的"该评委提出的 claim 数"之前根本没归因

指令包原文要求看板给出「该评委提出的 claim 数」。第一轮实现里 `asked` 数的是
"这一格被**任何人**问到几条"——把它标成某位评委的战绩是错的：
depth 席位的评委完全可能追问一条 evidence 维的 claim（追问咬住的是质疑点，不是维度），
按 claim 归属计数会让"本人追问数"永远等于席位数，归因整列名存实亡。

**修法**：`boardOf` 加第四参 `attribution`（`byClaim: claimId → personaId`，来自 `turn.personaId`）；
`BoardCell` 拆成两个口径——`asked`（全场，任何人问的都算）与 `askedByJudge`（占席评委本人）。
报告接口把归因表传进去；报告页格子里"本人问过 N"用朱红小标、
"他席问过"用灰标，两者不混淆。drill 场实测：陈评委本人问 2 条、另有 2 条是别的评委咬过去的。
没有归因表时 `askedByJudge` 恒为 0（不猜）；无席位的行同样恒 0（归因不落到空位上）。

### 补修 3：动效账 #4「引用命中脉冲 320ms」——全站最后一处动效

视觉稿里被引用的那一句在点开时闪一下朱红，之前一直没做。规格是"**仅 1 次**"：
`animation: quote-pulse 320ms ease-out 1 forwards`，跑完停在纸色，不循环。
**只在 `verified === 1` 时跑**——脉冲庆祝的是"逐字机检命中了原文"这一拍，
没命中的句子打开时不闪，给它同样的动效等于把"未命中"也画成"找到了"（颜色只编码数据）。
点另一格引用时 React 的 key 变化让元素重建，脉冲重跑一遍。
`prefers-reduced-motion` 下整体关闭。至此 §3.2 动效清单 **4/4 兑现**。

### 同步调整的测试口径

- `tests/stage4-ui.test.ts` 的「不新增动效」断言反转为「**不许超账**」：
  报告页只许有 `quote-pulse` 这一条 keyframes（`animation: none` 是关闭扫读光带的，不算动效）。

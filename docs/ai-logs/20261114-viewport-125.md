# 2026-11-14 · 浏览器 125% 下纵向一屏（视口自适应布局）

## 目标

用户原话：「调整一下页面布局尽量在浏览器125%的时候不要上下滑动」。

即把各页面在**浏览器 125% 缩放**下尽量压进一屏，不出现纵向滚动条。纯布局 / 间距调整，不碰功能、不改数据口径、不加依赖。

## Prompt 原文

> 调整一下页面布局尽量在浏览器125%的时候不要上下滑动

## 口径：125% 到底是多大

本机物理 2560×1600 + Windows 显示 150%，Chrome/Edge 里再按 125% 缩放：

- 物理 2560×1600 ÷ Windows 150% = 浏览器 CSS 视口 1707×1067
- 再 ÷ 125% = **1365×853**

这与 `progress.md` 里既定的录制口径一致（OBS 整屏 2560×1600 → 浏览器 125% → ffmpeg 缩 1920×1080）。所以验收视口就是 **1365×853**。

## 先建尺子：`scripts/probe-viewport.mjs`

改之前没有任何手段量"一屏装不装得下"。照抄 `scripts/probe-mobile.mjs` 的 CDP 骨架（无 puppeteer/playwright，Node 22+ 内置 WebSocket 手写极简 CDP 客户端），只换三处：

- 默认视口 1365×853、`mobile: false`、CDP 端口 9334
- 判定从"横向溢出"改成"纵向溢出"：`scrollH - clientH > TOLERANCE`
- 按 DOM 深度 ≤4 逐层取高度 >40px 的子块，按高度降序输出**纵向大户**（`--top N`、`--tolerance` 可调）

页面清单沿用 `data/app.db` 自动发现：`/`、`/upload`、最多 4 个 `/doc/{id}`、2 个 `/session/{id}`、最新 1 个 `/report/{id}`。

> **环境坑**：本机在文件沙箱内跑无头浏览器会 100% 假失败。DevTools 的命名管道被沙箱拒绝（`platform_channel.cc:187 Check failed: . : 拒绝访问`），`/json/version` 永远连不上，报"CDP 端口在 15s 内未就绪"。必须 `danger-full-access`。

## 改动

改动前逐个查了 `tests/` 的硬约束，确认：

- `tests/` 里**没有任何**针对 680px / `.cols` / `.drop` / `.mock-block` / `.wrap` / `min-height` 的高度断言；唯一高度断言是 `tests/cursor.test.ts:21` 的 `height: 1em`（光标）
- 首页 CSS/TSX **完全无断言**
- 全仓库 `100vh|dvh|svh|calc(100` **零命中**，所以引入视口单位不会和既有规则冲突
- 必须保留：`.report-cols` 的 `grid-template-columns: 1fr 1fr`（`tests/stage4-ui.test.ts:79`）、`@media (max-width: 860px)` 单栏（`:168-171`）、报告页禁十六进制（`:173-177`）、报告页只许 `@keyframes quote-pulse`（`:161`）

### `app/home.css`（首页）

所有大间距拦腰砍：`.wrap` 56/80 → 10/10、`.sect` 56 → 18、`.proof` 56 → 18、`.foot` 48 → 16、`.flow .step` 22 → 10、`.hero` 28 → 10、`.btn` 11px → 9px。

同时把 `.tagline` / `.sect .lede` / `.proof .tx` 的 `max-width: 62ch|64ch` 全改成 `none` —— 这个限宽是个隐蔽的纵向浪费：`ch` 按"0"字宽算约 0.5em，62ch 对中文只有 ~31 字宽，正文被强行提前折行，横向空出几百 px、纵向却多出好几行。

**→ 507px 超出归零。**

### `app/upload/upload.css`（上传页）

`.shell` 48/72 → 26/28、`.frame` 32 → 18、`.drop` 44px → 26px、`.mock-block` 20px/16px → 14px/12px。

**→ 109px 超出归零。**

### `app/doc/[id]/doc.css`（质疑点页）

间距收一轮（`.shell` 24/18、`.stat` 12/9、`.toolbar` 14/8、`.filterbar` 12/7、`.card` 12/14 + 8）之后仍超 **211px**，因为真正的元凶是写死的高度：

```css
.cols { height: 680px; }   /* 改前 */
```

680 + 头部 ~200 + padding 40/72 ≈ 1198，在 853 的视口里必然溢出。改成跟着视口走，**同时保住原来"三列齐底"的设计意图**：

```css
.cols { height: clamp(280px, calc(100vh - 430px), 680px); }
```

上限仍是 680px（大屏观感一字不变），下限 280px 保证极矮视口下列里还能看到两三张卡。430 是量出来的：正文起点 104 + 头部 + toolbar + filterbar + 页脚留白。

顺带把 `docs/ai-logs/20261107-board-scroll-session-tweak.md:97` 挂的那笔"列高写死 680px、未按视口自适应"的账还掉了。

**→ 345px 超出归零。**

### `app/report/[id]/report.css`（报告页）

报告页有 3970px 的真实内容（封面带 + 看板 + 8 张维度卡 + 4 条高风险 + 总建议 + 4 条审议轨迹 + 复练区），一屏装下不可能，目标是尽量压。

三轮都做的事：

1. **间距系统性收紧**（约 20 处）：`.report-shell` 80 → 20、`.report-cover-inner` 36/30 → 16/14、`.report-coverage` 12/9 + 20/14/18/10、`.report-col-title` 10/7 + 8/6、`.trace-strip` 14/9 → 10/7、`.tr-item` 14/12 → 8/8、`.tr-q` 1.85 → 1.7、`.tr-a` 1.75 → 1.65、`.high-item` 16 → 10、`.high-text` 1.75 → 1.6、`.high-quote` 1.8 → 1.6、`.report-advice p` 1.85/16 → 1.7/10、`.board` 20 → 14、看板表格各 padding 各减 2px、`.report-actions` 24 → 12、`.report-foot` 28 → 10
2. **`app/globals.css` 的 `--pad-card: 20px 22px` → `16px 18px`** —— 一处 token 同时收紧所有卡片内边距
3. **把「高风险清单」「审议轨迹」排成两列**（新增 `@media (min-width: 980px)`）：这两段竖排分别占 933px / 602px，是整页纵向浪费最大的两块。它们都是一条一条彼此独立的卡片，排两列不改变阅读顺序。阈值取 980px —— 低于它每张卡不足 420px，13.5px 正文会折得太碎
4. **报告页容器从 `var(--container)`（1080px）单独放宽到 1240px**：`/report` 是全站唯一用满 1080px 的宽页，横向余量给足一点，两栏文字少折行。只改这一页，不动全局 token

**→ 3117px 超出降到 1988px。**

## Bug 与修复过程

**Bug 1：探针 100% 假失败（沙箱）**

`node scripts/probe-mobile.mjs` 报 `CDP 端口 9333 在 15s 内未就绪（fetch failed）`。一开始以为是端口占用，换端口无效；前台跑 Edge 才看到真因 —— `[FATAL:mojo\public\cpp\platform\platform_channel.cc:187] Check failed: . : 拒绝访问。 (0x5)`，DevTools 的命名管道被文件沙箱拒绝，`/json/version` 根本不可达。试过 `--no-sandbox --single-process` 与 `--no-zygote --single-process --no-sandbox` 两组合，仍是超时。**结论：本机量布局必须 `danger-full-access`**，已记进本文件。

**Bug 2：PowerShell 不接受内联多参**

`Start-Process -FilePath $exe -ArgumentList 'a','b'` 报「找不到接受实际参数"System.Object[]"的位置形式参数」。要先 `$a = @(...)` 再 `-ArgumentList $a`。

**Bug 3：`--path /doc` 命中的是 Next 错误页**

`/doc` 不是路由（真实路由是 `/doc/[id]`），探针报"仍是骨架态或正文仅 105 字"。必须用完整 id。

**Bug 4（重要，踩了两次）：`npm run build` 会把运行中的 dev 服务打成 500**

`next build` 覆盖 `.next`，正在跑 `npm run demo` 的 dev server 立刻全线 500（`/api/health` 返回 500，页面变成骨架态）。第一轮复测时四个页面全报"仍是骨架态或正文仅 0 字"就是这个原因，**不是布局回归**。修法：kill 掉 demo 相关 node 进程 → `npm run demo` 重启 → 等 `/api/health` 回 `ok:true` 再测。

另外 `npm run demo` 是起在 **3000** 端口（不是 3111），探针默认 BASE 是 3111，所以要么带 `--base http://127.0.0.1:3000`，要么另起。

**Bug 5：批量改 CSS 用 `python -c` 做替换时有 5 处 MISS**

第一轮替换报告页时，`.tr-item` / `.report-advice p` / `.high-text` / `.high-q,.high-why,.high-sug` / `.tr-q` 五处没匹配上（原因是同一属性在同一文件里重复出现，`replace(a,b,1)` 只替第一处，且这几个选择器的多行格式与其他不同）。改成按选择器定位块（先 `s.index('.tr-item {')` 找起点、`s.index('}', i)` 找终点，只在块内替换）后全部生效。**教训：同一 CSS 属性在全文件多处出现时，必须按选择器块内替换，不能全局 `replace`。**
